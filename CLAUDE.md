# TrackFlow — Engineering Standards & Project Context

## What This Is
TrackFlow is a production workforce time tracking & monitoring platform (comparable to Hubstaff). Monorepo with three codebases:

| Component | Stack | Path | Runtime |
|---|---|---|---|
| Backend API | Laravel 12, PHP 8.2+, PostgreSQL 18, Redis 7 | `/backend` | Docker / Sail |
| Web Dashboard | Next.js 16, React 19, TypeScript 5.x, Zustand, TanStack Query v5 | `/web` | Node 20+ |
| Desktop Agent | Electron 42, Node.js, better-sqlite3, sharp | `/desktop` | Native binary |

## System Architecture
```

                    │        PostgreSQL 18              │
                    │   (multi-tenant, UUID PKs,        │
                    │    org_id scoping on all tables)   │

                               │

  (Next.js SSR)         │    └──► S3 / CloudFront (screenshots)
                        │
                   Reverb WebSocket (real-time updates)
```

## Non-Negotiable Engineering Rules

### 1. Data Isolation (Multi-Tenancy)
Every database query MUST be scoped by `organization_id`. The `GlobalOrganizationScope` trait handles this for Eloquent models. For raw/aggregate queries, add explicit `WHERE organization_id = ?`. A query that leaks data across orgs is a P0 security incident.

### 2. API Design
- All list endpoints: `->paginate()`, NEVER `->get()` for unbounded collections
- Response envelope: `{ "data": [...], "meta": { "current_page", "last_page", "total" } }`
- Errors: `{ "message": "Human-readable", "errors": { "field": ["..."] } }` (Laravel default)
- Auth: Bearer token via Sanctum. Access token (24h) + refresh token (30d)
- Versioning: All routes under `/api/v1/`
- Rate limits defined in `AppServiceProvider`: auth=10/min, general=1000/min

### 3. Code Organization
- **Controllers**: Thin. Validate input, call service, return response. Max ~30 lines per method.
- **Services**: `app/Services/` — all business logic. Constructor injection via Laravel DI.
- **Jobs**: Background work. Every job MUST have `$tries`, `$timeout`, `$backoff`, and `failed()` handler.
- **Policies**: Authorization logic. Every controller action that accesses a resource must `$this->authorize()`.
- **Models**: Eloquent with `$fillable`, UUID traits, relationship definitions. No business logic in models.

### 4. Frontend Patterns
- Data fetching: TanStack Query (`useQuery`/`useMutation`). Never raw `useEffect + fetch`.
- State: Zustand stores. Cleanup intervals on unmount and logout. No stale subscriptions.
- SSR safety: `typeof window !== 'undefined'` guard on all browser-only APIs.
- Error handling: Every query destructures `isLoading`, `isError` and renders both states.
- Role-based: Early return with `<PageLoading />` for unauthorized roles. No content flash.
- Layout: shadcn Sidebar primitive (`web/src/components/ui/sidebar.tsx`) with collapsible icon mode; mobile uses Sheet overlay.
- Charts: shadcn `ChartContainer` (`web/src/components/ui/chart.tsx`) wrapping Recharts primitives. Never use raw `ResponsiveContainer` — always wrap in `<ChartContainer config={...}>`. Use `ChartTooltip`/`ChartTooltipContent` and `ChartLegend`/`ChartLegendContent` from the chart component. Colors use CSS variables `--chart-1` through `--chart-5` via `hsl(var(--chart-N))` in `ChartConfig`.
- Dashboard layout: shadcn dashboard-01 design. Sidebar has 3 nav groups (Main / Analytics / Team) with role-based filtering. Area charts with gradient fills for both admin (hours + activity) and employee (hours) views.

### 5. Desktop Security
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` on ALL BrowserWindows
- ALL renderer ↔ main communication through `contextBridge` in preload script
- **Main window is a REAL application window, not a tray popup.** It was a `320x480` frameless, `skipTaskbar`, tray-anchored popup that hid on blur; it is now resizable (default `440x560`, floor `380x480`, no ceiling), present in the Dock/taskbar, and persists its full rect. Geometry + per-platform chrome rules live in `desktop/src/main/window-geometry.js` (pure, no Electron import, unit-tested — `popup-size.js` is gone). Native controls everywhere: macOS `titleBarStyle:'hiddenInset'` + `trafficLightPosition` (traffic lights float over the branded header row, which reserves 80px on the left), Windows `titleBarStyle:'hidden'` + `titleBarOverlay` (OS paints the caption buttons into that row, 138px reserved on the right, overlay height must equal `.titlebar` in `shared.css`), **Linux a plain native `frame: true` — never frameless**, because `titleBarOverlay` support varies by WM/compositor and an undecorated frameless window there is undraggable and unclosable. Renderer tags `<html>` with `platform-mac|platform-win|platform-linux` to drive the header reserve.
- **Close HIDES, it does not destroy** (`'close'` → `preventDefault()` + `hide()` unless `isQuitting`), so tidying the desktop can never kill a running timer. Quit stays deliberate (tray / Cmd+Q) and still runs the `before-quit` graceful stop + offline-queue flush. `app.on('activate')` re-shows on Dock/taskbar click — mandatory once close only hides. There is **no hide-on-blur**: the debounced blur handler and the macOS unfocused-ticks poll (`_startUnpinnedFocusWatch`, now a no-op) are retired, and `showPopup()` no longer re-anchors to the tray or forces the primary display — it restores where the user left it, applying only an off-screen rescue (a rect stranded by an unplugged monitor keeps its size but is re-centred). `alwaysOnTop` defaults **false** (pinning only ever existed to defeat hide-on-blur).
- **Pin across virtual desktops is Windows-only work.** `setVisibleOnAllWorkspaces()` puts a pinned window on every Space/workspace on macOS and Linux, but is a **documented no-op on Windows**, and Windows has no supported API for it (the shell's "Show this window on all desktops" is undocumented COM whose IIDs move with every Windows build). So on Windows the pinned window **follows the user**: Windows re-assigns a window to the ACTIVE virtual desktop when it is shown, so `hide()` + `showInactive()` (never `show()`/`focus()` — the user is typing elsewhere) teleports it there. Detection is free — Chromium marks a window on another virtual desktop as occluded, so `index-renderer.js` reports compositing state (`visibilitychange`, plus a one-rAF-per-700ms starvation backstop for builds that keep saying `visible`) over the `report-composited` IPC. Decision logic is pure and unit-tested in `desktop/src/main/virtual-desktop-follow.js`: Windows-only, **pinned-only**, and it must NEVER act on a window that is hidden-to-tray or minimised (that would resurrect a window the user dismissed) — plus a 400ms confirm, a 1.5s cooldown, and a give-up after 3 failed moves so a follow can never become a hide/show flicker loop. `showPopup()` likewise hides first when the window is known to be off-desktop, so a tray click brings the window to the user instead of dragging the user to another desktop. See `bugs/desktop-windows-pin-not-on-all-virtual-desktops.md`.
- **Application menu is set explicitly** — `null` on Windows/Linux so Electron's stock default menu bar (Reload / Toggle DevTools) never renders inside the frame; a real menu on macOS, because without one Cmd+C/V/A, Cmd+W, Cmd+M and Cmd+Q stop working there. `Cmd/Ctrl+Q` quits (it used to sign the user out); `Escape` hides to tray (it used to call `window.blur()` and depend on hide-on-blur). See `bugs/desktop-tray-popup-to-real-window.md`.
- Token storage: AES-256-GCM via Node.js `crypto`. NOT keytar, NOT safeStorage (both trigger macOS keychain popups on ad-hoc signed apps)
- Screenshots on macOS: window capture first (avoids wallpaper-only bug), screen capture fallback
- Screenshots on Linux/Wayland (Ubuntu 22.04+): `--enable-features=WebRTCPipeWireCapturer,PipeWireCapture` is appended before Chromium initialises so Electron captures via PipeWire (real compositor pixels, no black frames). Chromium 120 / Electron 28 caches the XDG portal session — the screen-picker dialog appears **once** on the first capture of a session; all subsequent `desktopCapturer.getSources()` calls in that session are silent. `WAYLAND_DISPLAY` is intentionally kept set so the activity-monitor can choose between Wayland-aware (ydotool) and X11 (xdotool) tool paths. Must be set before `app.requestSingleInstanceLock()`.
- **Logout conditions** (enforced in `api-client.js` interceptor): `forceLogout()` is ONLY triggered when token refresh returns HTTP 401 or 403 (genuine auth rejection: invalid/expired refresh token, password changed, token revoked). Network errors, timeouts, DNS failures, and 5xx server errors during token refresh do NOT trigger logout — the request simply fails and the user stays authenticated. This prevents the "unconditional logout" bug where transient network issues would log the user out.
- **Logout cleanup**: Both `forceLogout()` and `performLogout()` clean up: timer state, all services (activityMonitor, screenshotService, idleDetector, networkMonitor), powerMonitor/app listeners (`removeSessionListeners()`), timerSync interval, tray timer, offline queue, and encrypted token file.
- **Stop + upload on sign-out / quit**: `performLogout()` closes the live session LOCALLY (that IS the stop — no server call), then runs a bounded `sessionSyncWorker.syncNow({ignoreBackoff:true})` + `offlineQueue.flush()` (`LOGOUT_SYNC_BUDGET_MS`, 6s) while `apiClient` is still alive; `before-quit` does the same (2.5s) inside a 6s force-exit. `ignoreBackoff` matters: sign-out is exactly when a pending backoff window must not stand between the user and their tracked time. `WorkSessionStore.clearForLogout()` KEEPS every UNCONFIRMED row for the signed-in user (not just closed ones) and removes other accounts' rows plus this user's confirmed ones. A true force-kill runs no JS — recovery is local-first SQLite + the sync worker on next launch. See `bugs/desktop-signout-quit-unsynced-time-lost.md`.
- **Timer start mutex**: `startTimer()` still uses a `_startTimerInProgress` flag with `try/finally`, now only to stop a rapid double-click opening two local sessions. It can no longer produce duplicate SERVER entries — the uuid is generated once per session and the server upserts on it.
- **Local-first timer architecture**: local SQLite is the SOLE source of truth for tracked time, and the desktop is the only writer. `startTimer()` / `stopTimer()` / `switchProject()` and idle decisions write `timer_sessions` and RETURN — **no network call is on any of those paths**, so connectivity can delay an upload but can never affect or lose tracked time. Each session carries a client-generated uuid (`idempotency_key`) and a `revision` bumped by every local mutation; `synced_revision` records what the server confirmed, so a row is dirty iff `synced_revision <> revision`. `SessionSyncWorker` (`session-sync-worker.js`) pushes dirty rows to `POST /timer/sessions/sync` as an idempotent UPSERT. There is NO reconciliation layer — `reconcileTimerState()`, `syncOpenTimerFromServerStatus()`, `adoptServerStartedAt()` and their mutexes were deleted, because with one writer there is nothing to reconcile. Decision logic lives in `session-rules.js` (pure, no DB/Electron — better-sqlite3 is built for Electron's ABI and cannot load under Jest, so anything expressed as SQL is untestable in CI). See `bugs/offline-first-time-sync-refactor.md`.
- **Midnight split**: a live session crossing 00:00 is closed at the boundary and immediately reopened, so no entry ever spans two calendar days and daily rollups (`ReportService`, `AttendanceService::generateDailyAttendance()`, `DailyActivitySummaryService`, payroll) stay exact. The boundary is computed in the **ORGANIZATION's** timezone — the `timezone` field on `GET /agent/config`, which is `User::getTimezoneForDates()`, the same zone `TimezoneAwareDateRange` uses server-side. Splitting on the machine's local zone would mis-attribute hours for anyone travelling. Runs on the 1s tray tick (a purely local correctness operation — must happen regardless of connectivity) and LOOPS over every boundary crossed, so a machine asleep Friday→Monday produces one row per day. Expected UI effect: the elapsed counter resets at midnight, because the current session genuinely restarts.
- **05:00 purge**: `SessionSyncWorker.purgeIfDue()` deletes local rows that are closed AND have a `server_entry_id` AND a `confirmed_at` AND `synced_revision = revision` AND were confirmed more than 24h ago. Live, dirty and unconfirmed rows are structurally unreachable by that statement. Scheduled by comparing the most recent 05:00 boundary (org timezone) against `sync_meta.last_purge_at` — sleep-safe by construction, unlike a `setTimeout` a sleeping laptop would skip.
- **Broadcast isolation**: `TimerStarted`/`TimerStopped` are `ShouldBroadcastNow`, so dispatching them talks to Reverb synchronously over HTTP. `TimeEntrySyncService` QUEUES them and dispatches after the transaction commits, each wrapped in try/catch. Dispatching inline made a Reverb outage roll back the write and fail the sync — a websocket restart would have silently blocked all tracked time from uploading. Regression: `test_a_broadcast_failure_never_loses_the_session`.
- **Upload cadence — periodic ONLY (owner decision, 2026-08-03)**: tracking is local and continuous; uploading is a batch on a fixed **10-minute** interval (`SYNC_INTERVAL_MS`). There are NO event-driven pushes — start, stop, project switch, idle resolve, midnight split, wake and reconnect all used to fire one and no longer do. The only out-of-band flushes left exist to protect DATA, not dashboard freshness: launch (previous run's backlog), sign-out, quit, pre-update — after those the process may not be alive for the next tick. Accepted consequence: the web dashboard lags reality by up to one interval, including screenshots and heartbeats (both FK to a synced entry). Anything that reads a server total right after a local mutation MUST add `getUnsyncedCompletedSecondsForToday()` on top, or the displayed total drops by the work just finished (that is why the post-stop refresh does).
- **Offline sync protocol**: one cycle = health gate (`GET /health/live` — NOT `/health`, which probes S3 and counts failed jobs and is far too expensive to poll on every cycle) → push dirty rows in batches of 100 (max 10 batches/cycle) → confirm → **then** flush `offlineQueue`. That ordering is mandatory: screenshots and heartbeats FK to `time_entries.id`, which exists only once the owning session has synced. The row's `revision` is captured at SEND time and written back on confirm — using the row's CURRENT revision would mark a session the user stopped mid-flight as synced, and the purge would then delete it. Backoff 30s/60s/2m/5m/10m, reset on success; `{ignoreBackoff:true}` for launch/logout/quit/pre-update. Triggers: the 10-minute interval, plus launch, logout, quit and pre-update — nothing else. A `rejected` row is KEPT locally — a rejection is never a licence to delete tracked time.
- **Platform-specific network detection**: macOS/Linux use Electron's `net.isOnline()` directly. Windows adds a ping fallback (`ping 1.1.1.1` with 3s timeout) since `net.isOnline()` can report false positives on Windows.
- **Sleep/wake behavior**: On suspend, `_suspendedAt` is recorded and capture services are paused. On resume, the sleep gap is calculated and compared against the idle threshold. Long sleeps trigger the idle alert; short sleeps resume tracking normally. After any resume, `sessionSyncWorker.syncNow({ignoreBackoff:true})` pushes sessions and then flushes the offline queue. **If an idle alert is genuinely showing at the moment of lock/sleep**, `isIdleAlertActive()` routes suspend through `idleDetector.suspend()` instead of the hard auto-stop: the window is hidden (not destroyed), `idleStartedAt` is preserved, and the timer stays LOCALLY paused (there is no server-side pause any more) — non-idle lid-close is unaffected and still hard-stops. On resume, `idleDetector.resume()` + `setAlertState()` re-enters `ALERTING` with the same `idleStartedAt` (idle duration spans the sleep gap) and the alert re-shows so the decision is never lost. A live session that slept across one or more midnights is split into per-day rows on the first tray tick after resume. The idle alert itself is also hardened for multi-screen/multi-Space setups: an in-renderer WebAudio beep (no CSP change) plus a unique-id system notification guarantee a cue regardless of OS notification policy, macOS windows set `fullScreenable:false` and re-assert `setVisibleOnAllWorkspaces(true,{visibleOnFullScreen:true})` after `show()` so the alert overlays fullscreen Spaces, and Windows uses `flashFrame()`+`moveTop()` to defeat the foreground-lock. **The alert is a SINGLETON — exactly ONE window, on the display under the cursor.** The per-display mirrors are retired (they gave a two-monitor desk two identical modals, and a stale primary surviving a lock/sleep stacked more on top); `_destroyAllIdleAlertWindows()` sweeps every live alert window before a new one is created, on primary close, and in `dismissIdleAlert()`. Keep `showIdleAlert()` free of any `await` between its already-showing guard and the window assignment, or two concurrent calls can interleave into two windows. See `bugs/desktop-idle-window-multiscreen-and-sleep.md`.
- **Offline queue**: Stores heartbeat data, screenshot file paths, and timer start/stop events only — no tokens or sensitive credentials in SQLite. Queue is closed and nullified on both logout paths to prevent cross-user data leakage. `add()` MUST persist every field `flush()` reads back (`idempotency_key`, `activity_score`, `display_index`/`display_count`) — dropping them cost presign dedupe, display identity, and could make a `local-` screenshot look like an unresolvable orphan. The per-shot size cap in `ScreenshotService._queueForOffline()` (`MAX_OFFLINE_SCREENSHOT_BYTES`) must stay in sync with the queue's `MAX_SCREENSHOT_SIZE` (2MB).
- **Offline screenshot backfill**: `POST /screenshots/presign` accepts a capture for a CLOSED entry when `captured_at` falls inside `[started_at − 2min, ended_at + 2min]` and the entry ended within `offlineBackfillDays()`, which tracks `config('timer.max_past_skew')` (30d) rather than a fixed 7 days; live uploads keep a 5-minute grace. It MUST NOT be shorter than the session window: the agent flushes sessions BEFORE screenshots, so a narrower horizon accepts the entry and then permanently 422s its evidence. See `bugs/offline-screenshots-rejected-after-entry-closed.md`.
- **`pauseTimerForIdle()` is SYNCHRONOUS** (local-only since the offline-first refactor) — never `await` it or chain `.catch()`/`.then()` onto it. Doing so threw on every idle detection, after the pause had frozen tracking and before `showIdleAlert()` ran: no idle window on any OS, and the detector left wedged in DETECTED with no interval, which silently stood the idle hard-stop watchdog down for the whole session. `IdleDetector._check()` now wraps the `onIdleDetected` callback in try/catch and only re-arms to ALERTING when the callback left it in DETECTED (the `keep_idle_time` `always`/`never` policies resolve and re-start themselves). See `bugs/desktop-idle-alert-never-appears.md`.
- **Idle alert owns the timer while it is up**: idle is resolved ENTIRELY in local SQLite — `POST /timer/idle` is gone, along with `pauseTimerForIdle`'s server round-trip, `resumeTimerAfterIdle`, `reanchorFromOfflineIdle`, `retryIdlePauseIfUnsynced`, `isIdlePauseAuthoritative` and the `idle_discard` queue type. "Continue tracking" closes the live session at `idleStartedAt` and opens a new one at NOW (one SQLite transaction), so the idle gap belongs to no session. **Two instants, not one**: `closeAndReopen(id, atIso, {reopenAtIso})` defaults to CONTIGUOUS (correct for project switch and the midnight split — no instant may belong to no session) and the idle discard is the ONE caller that must pass a later `reopenAtIso`. Passing a single instant does not discard the gap, it moves it into the successor row and still bills it — that shipped, and cost every idle cycle its gap (`bugs/desktop-idle-continue-still-bills-the-idle-gap.md`). Note the trap that hid it: `idle-discard-split.test.js` asserts the arithmetic against a MIRROR of `handleIdleAction` (index.js cannot be imported under Jest), so mirrors must be pinned to the real call site or they pass while the code is wrong; "Stop timer" closes at `idleStartedAt` without reopening. Pre-idle work is credited measured to idle-START, never idle-end — measuring to idle-end double-counts the discarded gap. `keep`/`reassign` remain DISABLED (owner policy, 2026-07-16) and the refactor does not revive them; note the server can no longer enforce that policy, since the sync endpoint receives opaque sessions (see the Known Consequences section of `bugs/offline-first-time-sync-refactor.md`). The idle WATCHDOG still stands down while an alert is showing, and the popup/tray LOCK (`idle-lock` IPC + `idleLocked` on `get-timer-state`) is unchanged.
- **Today totals**: `todayTotalGlobal` is the COMPLETED all-projects sum (the tick adds live elapsed). It must only ever be fed the never-scoped `all_projects_today_total` — `today_total` is project-scoped whenever a project id is passed. `GET /timer/today-total` and `/timer/status` are still read on a cadence, and are the ONLY server input the desktop takes about time: they include MANUAL entries, which the agent does not own and cannot compute locally. Completed local sessions the server has not seen are added on top via `getUnsyncedCompletedSecondsForToday()`, so offline time stays visible instead of appearing to reset on reconnect. See `bugs/desktop-all-projects-total-resets-on-start.md`.
- **API timeouts**: session sync uses 30s (a 100-session batch after a long offline stretch does real work server-side); the health probe uses 5s; screenshot uploads 30s; default 15s.

## Multi-Organization Authentication

Users can belong to multiple organizations (same email, different `organization_id` in `users` table). The auth system handles this:

### Login Flow (email/password & Google OAuth)
1. Backend finds ALL User rows matching the email/Google ID
2. If single org: direct login (original behavior)
3. If multiple orgs: returns `{ "requires_org_selection": true, "organizations": [...] }`
4. Client shows org selector, user picks one
5. Client calls `POST /auth/select-organization` with credentials + `organization_id`

### API Endpoints
| Endpoint | Auth | Purpose |
|---|---|---|
| `POST /auth/select-organization` | Public | Complete login after multi-org detection |
| `GET /auth/organizations` | Sanctum | List all orgs for the current user's email |
| `POST /auth/switch-organization` | Sanctum | Switch to different org (issues new tokens) |

### Frontend Components
| Component | Path | Purpose |
|---|---|---|
| OrgSelector | `web/src/components/org-selector.tsx` | Login-time org picker (Card UI) |
| OrgSwitcher | `web/src/components/org-switcher.tsx` | Dashboard header dropdown to switch orgs |
| Sidebar | `web/src/components/ui/sidebar.tsx` | shadcn Sidebar primitive (collapsible, mobile sheet, keyboard shortcut Cmd+B) |

### Desktop Google OAuth
- Uses OAuth Authorization Code flow via system browser
- Starts temporary local HTTP server on `127.0.0.1` for the callback
- Exchanges auth code for ID token, sends to `POST /auth/google`
- Requires `TRACKFLOW_GOOGLE_CLIENT_ID` and `TRACKFLOW_GOOGLE_CLIENT_SECRET` env vars

### Invitation-Aware Google Signup
- When a new Google user signs up, the backend checks for pending invitations
- Pending invitations are auto-accepted: user is added to those orgs with the invited role
- A personal org is also created so the user always has at least one

## Manual Time Entry Approval Workflow

Extends the pre-existing manual entry system (`TimeEntryController::store()` with `type='manual'`, `is_approved`/`approved_by`/`approved_at`, `POST time-entries/{id}/approve`) with an explicit, auditable status machine.

- Migration `2026_07_07_000001` added `time_entries.approval_status` enum `['pending','approved','rejected']` (DEFAULT `'approved'`), `submitted_by` (FK users, `nullOnDelete`), `rejection_reason`. Existing rows backfilled to `approved` in batches of 5k. Partial indexes `idx_te_pending` (org+user+started_at WHERE pending) and `idx_te_org_status_started` (org+status+type+started_at).
- **`approval_status` is the authoritative state**; `is_approved` is kept as a synced boolean mirror by every manual write path (create/approve/reject/update-reset) for backward compatibility with older readers. Tracker/idle entries created by `TimerService` always land `approval_status='approved'` via the DB default — they are never queued.
- `ManualTimeEntryService` (`backend/app/Services/ManualTimeEntryService.php`): `create()` — an employee with no `time_entries.approve` scope covering themselves lands `pending`; a manager/PM whose approve scope (organization or project) covers themselves is auto-approved; time logged on behalf of a team member by an authorised user is auto-approved, and the target user is always resolved WITHIN the actor's org (a cross-tenant `user_id` can never attach to an entry). `approve()`/`reject()` — self-approval is blocked (403 if the approver is the entry's `submitted_by` or `user_id`) and only a `pending` entry can be resolved (422 "already resolved" otherwise). `listPending()` — role-scoped (organization=all, project=team). `canActorApprove()` — shared predicate reused by the update path.
- **Self-edit resets to pending**: if `TimeEntryController::update()` is called on a manual entry by someone who is NOT an authorised approver of that entry (`canActorApprove()` false — e.g. the employee editing their own already-approved entry), the entry is RESET to `approval_status='pending'` (clears `approved_by`/`approved_at`/`rejection_reason`) and requires re-approval. Tracked/idle entries are untouched by this rule.
- **Aggregate exclusion rule — filter on `approval_status='approved'`, NOT `is_approved`.** ~18 read paths enforce this: `ReportService` (summary/team/projects/payroll/analytics/timeline/timeLogs/detailedLogs), `TimesheetController::submit()`, `AttendanceService::generateDailyAttendance()`, `DailyActivitySummaryService`, `SendWeeklyReportJob`, `DashboardController` tracked totals. Pending/rejected manual entries are invisible to every report, payslip, attendance rollup, and dashboard total until approved. `ReportService::flushForOrg($orgId)` busts cached report totals on every create/approve/reject/update/destroy of a manual entry by bumping a per-org cache-generation counter (`orgCacheVersion()`) — needed because the default database cache driver has no tag-based flush.
- Routes (Sanctum, gated by `permission:time_entries.approve`): `GET time-entries/pending` (registered BEFORE the `time-entries` apiResource wildcard so `pending` is never captured as a `{time_entry}` id), `POST time-entries/{id}/reject`. The existing `POST time-entries/{id}/approve` now delegates to the service (pending-only precondition + self-approval guard).
- Web: `web/src/app/(dashboard)/time-entries/approvals/page.tsx` (approval queue, gated on `time_entries.approve`); `web/src/components/time-entries/` (`ManualTimeEntryDialog`, `ApprovalStatusBadge`, `UserCombobox`, `ProjectCombobox`); `web/src/hooks/time-entries/` (`use-manual-entry`, `use-pending-approvals`). `time/page.tsx` gained a "Log Time" button + `ApprovalStatusBadge` on entries. Nav: "Time Approvals" (Main group, `time_entries.approve`).

## PM Project-Time Report + Export

Per-entry time breakdown for project managers, filterable by project(s)/resource/period, with CSV and PDF export.

- `ProjectTimeReportService` (`backend/app/Services/ProjectTimeReportService.php`) + `ProjectTimeReportController` + `backend/resources/views/reports/project-time.blade.php` (PDF via `barryvdh/laravel-dompdf`, already a dependency).
- **Only `type='tracked'` AND `approval_status='approved'`** rows are ever reported — pending/rejected manual entries never appear.

### Attendance Check-in / Checkout (Module 3.1 — multi-session)
Manual clock-in/clock-out layer on top of `attendance_records`, distinct from the tracker-derived signal computed by `AttendanceService::generateDailyAttendance()`. The two RECONCILE, never conflict: a physical `check_in_at` elevates a computed `absent`/`half_day` to `present` in `generateDailyAttendance()`, which deliberately excludes every check-in column from its update payload so the check-in rollup columns are never clobbered by the nightly job. Users can check in/out multiple times per day — each pair is a row in the child table `check_in_sessions`, and `attendance_records` carries the day-level rollup.
- Table `attendance_policies`: one active row per org (`unique(organization_id)`, softDeletes, `GlobalOrganizationScope`). Columns: `check_in_time` (default `11:30:00`), `late_threshold` (`11:45:00`), `checkout_time` (`20:30:00`), `timezone` (`Asia/Karachi`), `allow_early_check_in` (default `false` = hard pre-window block), `is_active`. Times are wall-clock strings, not datetimes — comparisons happen in the ORG timezone via `Carbon::parse("{$date} {$time}", $tz)` rebuilt per-date so DST transitions are handled correctly. Server `now()` is the only authoritative instant; client-sent timestamps are ignored — there is no offline backfill in v1 (regularizations cover corrections).
- Table `check_in_sessions` (one row per check-in/checkout pair): `id`, `organization_id` (`GlobalOrganizationScope` via `BelongsToOrganization`), `user_id`, `attendance_record_id` (FK `cascadeOnDelete`), `seq` (1-based per-day sequence), `check_in_at` (UTC, authoritative), `check_out_at` (nullable while open), timestamps, softDeletes. Indexes: `idx_cis_org_user_checkin` on `(organization_id, user_id, check_in_at)`; partial `idx_cis_open` on `(organization_id, user_id, check_in_at) WHERE check_out_at IS NULL AND deleted_at IS NULL` (backs the open-session lookup for checkout + the backstop); partial `idx_cis_record` on `(attendance_record_id) WHERE deleted_at IS NULL`. Model `App\Models\CheckInSession` has `scopeOpen()`; `AttendanceRecord::sessions()` is a `hasMany` ordered by `seq`.
- `attendance_records` gained `sessions_count`; its check-in columns are now **rollups** recomputed by `CheckInService::recomputeRecordRollups()` on every check-in and checkout, never mutated directly: `check_in_at` = FIRST session's start (drives late; fixed after session 1), `check_out_at` = LAST CLOSED session's checkout (NULL until the first checkout, and NOT cleared when a later session opens — see `AttendanceService::serializeRecord`'s open-session guard below), `worked_seconds` = SUM of closed session durations (inter-session gaps excluded; null when no session has closed), `sessions_count` = number of sessions that day, `is_early_checkout`/`check_out_early_minutes`/`check_out_overtime_minutes` = recomputed from the LAST closed checkout vs `checkout_time` (early flag clears if a later checkout lands `>= checkout_time`, and overtime then computes from that checkout), `check_in_status`/`check_in_late_minutes`/`check_in_flags` = owned by the FIRST check-in only and never touched by later sessions.
- **Boundary rules**: before `check_in_time` with `allow_early_check_in=false` → 422 on EVERY check-in (not just the first), no session created. Check-in `<= late_threshold` (including exactly `11:45:00`) → `on_time`; after → `late`, with `check_in_late_minutes` measured from `late_threshold` (not `check_in_time` — the grace window is free) — evaluated once, on session 1. Checkout `< checkout_time` → `early_checkout` + early minutes; `>= checkout_time` (including exactly `20:30:00`) → normal, with overtime minutes once past it — evaluated against the LAST closed checkout each time. Late and early-checkout can coexist on the same record. **Multi-session**: a user may check in/out any number of times per day. Check-in returns 422 if a session is already open ("You already have an open check-in. Please check out first."). Re-checking in after a checkout is now ALLOWED and starts a new session (the v1 single-pair limit — and its "re-check-in after checkout → 422" behavior — is REMOVED; an accidental early checkout no longer locks the user out for the day). Checkout requires an open session (else 422) and must land strictly after that session's `check_in_at` (else 422).
- **Concurrency**: `checkIn()`/`checkOut()` run inside `DB::transaction()` with `lockForUpdate()` on the day's `attendance_records` row, gated on an open-`check_in_sessions`-row check — `unique(org, user, date)` on the day row alone is insufficient because the nightly job may pre-create it, and because multiple sessions can legitimately exist per day. Lock order is always record → session (`checkOut()` locks the record before re-fetching the session under lock) so two devices racing on the same user land exactly one session, never a deadlock.
- **Forgot-checkout / backstop**: a checkout after midnight still links to the prior day's open session (36h lookback; `worked_seconds` spans midnight via absolute-instant diff). `CloseStaleCheckInsJob` (`$tries=3`, `$timeout=300`, `backoff=[60,120,300]`, `failed()` handler) → `CheckInService::autoCloseStaleCheckIns($orgId)` finds OPEN `check_in_sessions` whose parent record's org-local date is in the past, flags the RECORD `missing_checkout` + `check_in_flags.auto_closed`, and recomputes rollups — it LEAVES the session's `check_out_at` NULL (never fabricates a checkout) so already-closed sessions' worked sum is preserved and the open one stays available for regularization. Scheduled `dailyAt('03:00')` in `routes/console.php` beside `generate-daily-attendance`. Per project convention the Laravel scheduler is DISABLED on dev and only runs in prod — on dev, trigger the backstop manually via `CheckInService::autoCloseStaleCheckIns($orgId)`. A next-day check-in is never blocked by a prior day's open row (lookups are keyed off the current org-local date).
- **Weekend/holiday/on-leave check-in**: allowed and recorded; status priority is preserved (Holiday > On Leave > Weekend > ...) and an advisory `check_in_flags` entry surfaces the anomaly to managers rather than blocking it. Known limitation: the off-day/weekend flag currently hardcodes Sat/Sun and does not yet honor a custom shift's `days_of_week`.
- `CheckInService`: `getPolicy()`/`updatePolicy()`, `checkIn()`, `checkOut()`, `recomputeRecordRollups()` (private; recomputes the day rollup from the record's session set — called after every check-in/checkout and by the backstop), `getTodayStatus()`, `listCheckIns()` (role-scoped), `summarize()`/`summaryRowGenerator()` (per-employee rollup), `detailRowGenerator()` (CSV detail rows), `autoCloseStaleCheckIns()`, `scopedUserIds()`.
- **Role-scoping + permissions**: `attendance.check_in` (every non-owner staff role — self-service clock in/out), `attendance.view` (gates the check-in list/summary/today endpoints; `CheckInService::scopedUserIds()` narrows the actual rows to self/team/org), `attendance.view_all` (org-wide visibility, decided in the service layer — granted to `org_manager`, `hr_manager`, `finance_manager`; owner sees all via permission bypass, not an explicit grant), `attendance.export` (CSV export, same grant set as `view_all`), `attendance.manage_policy` (edit check-in windows — `org_manager` + `hr_manager` only; `finance_manager` intentionally excluded). Enforced via route `permission:` middleware plus `CheckInService::scopedUserIds()` for row-level scoping. CSV export neutralizes formula injection (strips leading `=`,`+`,`-`,`@`,tab,CR) and streams via `cursor()`/`LazyCollection` so month × all-employees exports stay memory-bounded.
- Routes (all under `/api/v1/hr/`, Sanctum; static routes registered before the `attendance/{record}` wildcard to avoid route-model-binding collisions): `POST attendance/check-in`, `POST attendance/check-out`, `GET attendance/today`, `GET attendance/check-ins`, `GET attendance/check-ins/summary` (`period=day|month`, `date`/`month`, optional `user_id`), `GET attendance/check-ins/export` (CSV; `period`/`date`/`month`/`user_id`/`view`), `GET attendance/policy`, `PUT attendance/policy`. API endpoint shapes are unchanged by the multi-session redesign; `GET attendance/today` additionally returns `has_open_session`, `can_check_in`, `can_check_out`, `sessions_count`, `closed_worked_seconds`, `open_check_in_at`, and a `sessions[]` array (`seq`, `check_in_at`/`_local`, `check_out_at`/`_local`, `worked_seconds`, `worked_hhmm`, `is_open`) alongside the existing day-rollup keys. The check-in detail CSV export gains `Sessions`, `"First In"`, `"Last Out"` columns (header: `Employee, Email, Date, Sessions, "First In", "Last Out", "Total (HH:MM)", Status, "Late (min)", "Early (min)", "Overtime (min)", "Missing Checkout"`); the summary CSV is unchanged.
- `AttendanceService::serializeRecord` is open-session aware: an eager `withCount(['sessions as open_sessions_count' => ...])` (with a `recordHasOpenSession()` fallback when not eager-loaded) nulls the displayed `clock_out`/`check_out_at` while a later session is still open, so a stale last-closed checkout is never shown as "checked out". `generateDailyAttendance` still excludes check-in columns from its update payload.
- Frontend: `CheckInCard` (`web/src/components/hr/CheckInCard.tsx`) is a state machine — `not_checked_in` (Check In button) / `live` (day-total LIVE ticker in `HH:MM:SS` via `formatElapsed`, computed from `closed_worked_seconds` + the open session's elapsed time via clock offset; the interval only forces a re-render, it never accumulates — same lesson as the desktop local-first timer fix) / `idle_can_recheck` (frozen day total + "Check In again" button). Renders today's session list (`in at X → out at Y` + per-session duration; an open session shows "in progress"). Late/early/flag badges via `CheckInStatusBadge`. Formatting is now split by purpose: the live ticker uses `HH:MM:SS` (`formatElapsed`); every totals display (`CheckInCard`, `hr/attendance`, `hr/attendance/team`, `hr/attendance/report`) uses the new `formatDuration` helper (`"Xh Ym"`) — this replaces the v1 ambiguous "00:02 worked" formatting. Mounted on the employee dashboard (`web/src/app/(dashboard)/dashboard/page.tsx`) and `hr/attendance` page. Policy settings page `hr/attendance/settings` (`attendance.manage_policy`). All-employees rollup + CSV export page `hr/attendance/report` (`attendance.view_all`/`export`). Shared download helper `web/src/lib/download.ts` is reused by reports and check-in export. Pure time/format helpers in `web/src/lib/check-in-time.ts` (`computeClockOffset`, `elapsedSeconds`, `formatElapsed`, `formatDuration`, `formatHhmm`, `deriveCheckInBadgeStatus`). Data hooks in `web/src/hooks/hr/use-check-in.ts`.
